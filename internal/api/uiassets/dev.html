Qiyan

Developer entry — the open control layer

Any agent host can use Qiyan's control capability through this local, versioned HTTP/JSON API — the same API the console and the built-in Claude Code integration use. No private imports, no SDK required.

Endpoints (v1)

Ask before you act

curl -s -X POST http://127.0.0.1:8760/v1/authorize \
  -H "Authorization: Bearer $AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"missionId":"mi_...","taskId":"ta_...","action":{"kind":"file.read","tool":"note.read","path":"D:/work/note.txt"}}'

ALLOW → run it. DENY → do not. REQUIRE_APPROVAL → wait, then retry the exact action; an approval authorizes one execution of exactly that action. UNKNOWN is never a green light. If your host can bypass the API, Qiyan does not claim to control that path — the coverage table below says what is actually enforced.

See it working: the reference host

The repository ships cmd/qiyanhost — a small Go program that does exactly the above: registers, asks, obeys, reports. Run it against this service to watch allow / deny / approval live:

go run ./cmd/qiyanhost --addr 127.0.0.1:8760 --token TOKEN --mission mi_... --task ta_... --workdir D:/scratch
