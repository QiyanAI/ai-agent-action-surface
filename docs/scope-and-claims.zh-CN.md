# 范围与声明边界

本文档如实说明本仓库当前能做什么、不能做什么，确保读者与自动化系统都不会把
“意图”误当作“已实现能力”。若代码与本文档不一致，以本文档为准，代码即为错误。

| 能力 | 说明 | 证据 |

| 执行前门禁 Hook | `qiyan hook pretooluse`：真实执行前阻断；任何失败都以退出码 2（拒绝）结束；绝不虚构决策 | Hook 测试；R02-00 的 40+ 次真实嵌套运行矩阵 |

## 关于 Claude Code 版本的具体结论（本机实测）

| 版本 | 拒绝能阻断？ | 故障时失败即拒绝？ | 支持范围 |
| --- | --- | --- | --- |
| ≥ 2.1.295（实测 2.1.295、2.1.300） | 是 | 是（`onFailure: "block"`） | 完整保护；连接器仍会按机器实测复核 |
| 2.1.292、2.1.68 | 是 | **否——失败即放行** | 仅显式拒绝；连接器拒绝声称其失败即拒绝，并说明原因 |

版本号从来不是依据。`qiyan connect claude` 会在实际机器上运行探针并记录实测等级。

## 未实现或明确不宣称的内容

- **没有操作系统级沙箱。** 路径检查是词法与范围级别的；符号链接竞态、以及
  Qiyan 接入点直接之外的进程行为，都不在可证明范围内，并会如实呈现。
- **不承诺控制无法解释的命令。** 无法识别的命令、无法识别的工具、路径形式的
  程序、含 shell 元字符的命令，一律进入审批（或拒绝），绝不静默放行。
- **Shell 命令：不存在任何按程序名称的自动放行——每一条 Shell 命令都等待你的
  批准；而且这不是沙箱。** 对任何“安全程序”清单的历次独立复核都不断产生同类
  反例——`go test` 运行项目代码、`go env -w/-u` 写持久配置、`git status` 会执行
  配置好的 `core.fsmonitor` 钩子、`sort -o`／`uniq in out`／`date -s`／
  `hostname NAME` 带有写入或状态模式、`file --compile -m …` 会写出编译产物——
  因为任何程序的行为都能被纯字符串检查无法验证的参数、配置或环境重定向，而
  仓库本地配置恰是被门禁的 Agent 自己可写的。因此机制本身已被移除：没有名称
  白名单，也没有参数黑名单；Shell 操作默认永不执行。**不变的部分：** 具有明确
  语义的原生工具——Read、Glob、Grep 以及会话记录类工具——保留各自规则，在授权
  范围内继续自动执行，且经由它们的越界访问仍是硬性 DENY；kind 或 tool 不在任务
  范围内的 Shell 操作同样被 DENY，而不是仅仅询问。在分类器之外，边界同样被如实
  说明：Shell 命令名经由会话的 PATH 与环境解析，那是用户自己的信任域——Qiyan
  验证的是其门禁的决策，不是用户工具链的安装本身。
- **绝不启动或连接 MCP Server。** 实验室只读取其配置。
- **不强制阻断任意网络。** 对外工具操作走审批门禁；覆盖表如实说明哪里被强制。
- **不支持其他运行时。** 只有 Claude Code 是正式支持的接入；Cursor、ChatGPT、
  Codex、n8n 等均不在宣称范围内。
- **没有 SaaS、没有账号、没有遥测。** 一切都在本地。
- **不自动修复任意漏洞。** 实验室的自动应用仅限它预览并验证过的禁用规则。
- **状态只有一个写入进程。** `qiyan serve` 是唯一写入者；Hook 与 CLI 都是客户端。
  服务不可达时，受保护操作一律拒绝（失败即拒绝），绝不放行。

## 未发布

本项目尚未发布任何产品版本。发布演练仍只是带来源证明的测试工件。

R03 早期体验候选（`Candidate Build` 工作流）是**测试构建**：未签名的裸二进制，
明确标注 `EARLY ACCESS / TEST BUILD / NOT PRODUCTION-CERTIFIED`，以工作流工件
形式分发，附带 SHA-256 校验和与构建来源证明（将每个二进制绑定到其构建时的确切
提交）。它们不创建任何 GitHub Release，不附带任何支持或兼容性承诺，只说明实际
构建覆盖的平台——而不是"支持的平台列表"。下载的候选程序必须留在原处：已安装的
Claude Code 集成指向该二进制的绝对路径，移动或删除它会让门禁按失败即拒绝工作，
从而阻止该项目中的工具调用。
